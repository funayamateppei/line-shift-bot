当番Bot デプロイ手順

Google Apps Script と LINE 公式アカウントを無料で用意し、Bot を動かすまで。所要 30 分ほど。必要なのは Google アカウントと LINE アカウントだけ。

1LINE2シート3GAS4公開5Webhook6トリガー7グループ8確認

あらかじめ控えるもの

途中で 4 つの値が出てきます。メモ帳に貼っておくと楽です。

  • チャネルアクセストークン（手順 1）
  • 管理者のユーザーID（手順 1）
  • スプレッドシート ID（手順 2）
  • ウェブアプリ URL（手順 4）

1LINE 公式アカウントを作る

公式アカウントを作り、Messaging API を有効にする

作る場所が変わりました。 LINE Developers コンソールから Messaging API チャネルを直接作ることはできません。先に LINE 公式アカウントを作り、そこで Messaging API を有効にします。
  1. LINE Official Account Manager で LINE 公式アカウントを作る
    • アカウント名：表示される Bot の名前（例：当番Bot）
    • 料金プランは「コミュニケーションプラン」（無料、月 200 通）のままでよい
  2. 右上の 設定 → 左メニューの Messaging API → Messaging API を利用する
    • ここでプロバイダーを選ぶ（新規で作ってよい）
    • 有効になると「ステータス：利用中」と Channel ID が表示される
  3. 同じ 設定 の 応答設定 を開き、次の状態にする
    • チャット：オフ
    • あいさつメッセージ：オフ
    • 応答メッセージ：オフ
    • Webhook：いまはオフのまま（手順 5 で URL を入れてからオンにします）
    オンのままだと、Bot の返事とは別に定型文が届いてしまいます。
  4. 設定 → アカウント設定 で 2 つ変える
    • グループトーク・複数人トークへの参加：有効
      ここが無効だと、グループに招待しても Bot が参加できません。この Bot はグループに入れないと成立しません。
    • 写真や動画の受け取り：受け取らない
      この Bot は画像を一切使いません。1 対 1 のトークで送信機能が消えるだけで、グループでの会話には影響しません。
  5. Messaging API の画面の一番下「LINE Developersコンソール」のリンクからチャネルを開く
    有効化のときに選んだプロバイダーの下に入ります。自分で作った別のプロバイダーを見ていると一覧に出てこないので、このリンクから辿るのが確実です。
  6. チャネルの Messaging API 設定 タブで「チャネルアクセストークン（長期）」を 発行 → チャネルアクセストークン として控える
    「アサーション署名キー」は別物です。触りません。
  7. チャネル基本設定 タブの一番下「あなたのユーザーID」を 管理者のユーザーID として控える（U で始まる 33 文字）
管理者もメンバーの一人です。あとで自分の Bot を友だち追加して、都合がつく日を答えることになります。

2スプレッドシートを用意する

空のシートを 1 つ作るだけ

  1. Google スプレッドシートを新規作成（名前は何でもよい）
  2. URL の /d/ と /edit の間の文字列を スプレッドシート ID として控える 
    https://docs.google.com/spreadsheets/d/ここが ID/edit

タブは Bot が自動で作るので、何もしなくてよい。

3GAS を用意する

コードを貼って、初回セットアップを 1 回動かす

  1. https://script.google.com/ で「新しいプロジェクト」
  2. プロジェクト名を付ける（例：当番Bot）
  3. 既定の コード.gs の中身を消して、このリポジトリの dist/コード.gs をまるごと貼り付ける
    • GAS のエディタにはフォルダを置けないので、12 ファイルを 1 枚にまとめてあります。貼るのは 1 回だけ
    • appsscript.json は プロジェクトの設定 → 「appsscript.json をエディタで表示」をオンにしてから、リポジトリの src/appsscript.json の中身を貼る
  4. 貼ったコードの先頭にある 2 つの値を書き換える 
    var SPREADSHEET_ID = '（スプレッドシート ID）';
var CHANNEL_ACCESS_TOKEN = '（チャネルアクセストークン）';
  5. エディタ上部の関数選択で setup を選び 実行
    • 初回は権限の許可を求められます。「このアプリは Google で確認されていません」と出たら 詳細 → 「（プロジェクト名）（安全ではないページ）に移動」 → 許可
      審査は他人に配布する公開アプリのための仕組みです。自分のアカウントで自分の書いたスクリプトを動かすときは通す必要がありません。デベロッパー欄が自分のアドレスになっていることだけ確かめてください。
    • スプレッドシートに 5 つのタブ（設定／名簿／状態／回答ログ／当番_YYYY年度）ができる。もとからあった空のタブは自動で消えます
  6. スプレッドシートの 設定 タブを開き、管理者ID に 管理者のユーザーID を貼る
    • グループIDは手順 7 で Bot を招待すると自動で入る
    • お知らせ日（15）と締切日（25）は既定のままでよい。変えるときは ▼ から 1〜28 を選ぶ

4ウェブアプリとして公開する

LINE から呼べる URL を作る

  1. GAS エディタ右上 デプロイ → 「新しいデプロイ」
  2. 種類：ウェブアプリ
    • 実行ユーザー：自分
    • アクセスできるユーザー：全員
  3. 「デプロイ」→ 出てきた URL を ウェブアプリ URL として控える 
    https://script.google.com/macros/s/xxxxxxxx/exec
コードを直したときは デプロイを管理 → 鉛筆 → バージョン「新バージョン」→ デプロイ。URL は変わりません。
設定 シートの値を変えるだけなら再デプロイは不要です。

5Webhook をつなぐ

LINE に GAS の URL を教える

  1. LINE Developers のチャネル → Messaging API 設定 → Webhook設定
  2. Webhook URL に ウェブアプリ URL を貼って「更新」
  3. 「Webhook の利用」を オン
  4. Official Account Manager の 設定 → 応答設定 に戻り、Webhook を オンにする
「検証」ボタンは 302 エラーになります。これは正常です。 GAS のウェブアプリは /exec へのリクエストを必ず script.googleusercontent.com へ転送する作りで、検証ボタンはその転送を追いません。実際の配信は動きます。
本当に動いているかは、手順 8 で Bot に一言送って返事が来るかで確かめてください。
転送先が accounts.google.com の場合だけは本当の失敗です。手順 4 の「アクセスできるユーザー」が「全員」になっていません。

6定時トリガーを設定する

毎朝 9 時台に 1 回動かす

  1. GAS エディタ左の時計アイコン トリガー → 「トリガーを追加」
  2. 実行する関数：daily
    イベントのソース：時間主導型
    時間ベースのトリガー：日付ベースのタイマー
    時刻：午前 9〜10 時
  3. 保存

15 日なら「始めますか」、25 日なら未回答一覧を管理者に送ります。それ以外の日は何もしません。

7グループに入れる

Bot を招待して、全員に友だち追加してもらう

  1. LINE で Bot を友だち追加（QR コードは Messaging API 設定 タブにある）
    公式アカウントを作った本人は、はじめから友だちになっています。 その追加は Webhook を用意する前に済んでいるので、Bot はイベントを受け取れず、名簿 に載りません。
    直し方：一度ブロックして、すぐブロック解除する。 友だち追加のイベントが飛び直し、名簿に入ります。名簿 に自分の行ができたか確かめてください。
  2. 当番を決めるグループに Bot を招待 → Bot が「友だち追加してください」と送る。設定 の グループID が自動で入る
    • 入れない場合は手順 1 の「グループトーク・複数人トークへの参加」が有効か確認
  3. 全員に友だち追加してもらう（管理者を含む。管理者もメンバーの一人です）
Bot はグループに入る前からいた人を見つけられません。 無料プランではグループのメンバー一覧を取れないためです（一覧の API は 403 を返します）。全員の友だち追加が済むまで、その人には当番の相談が届きません。詳しくは運用マニュアル 1-1。

8動作確認

ここまでの設定が本当に通っているかを見る

  1. 管理者の 1 対 1 トークで Bot に何か一言送る → 「いま進めているものはありません。」と返れば Webhook が通っています
  2. 返事の下に 開始 状況 中止 が並ぶ。これが管理者のメニュー
  3. 開始 → 対象月 → 部制 → 日数 → この日程でOK まで試し、メンバーにカレンダーが届くことを確認
  4. スプレッドシートの 名簿 に人が並び、状態 が進んでいることを確認
  5. 確認が終わったら 中止
反応まで 2〜4 秒かかります。 Google 側の起動時間です。返事が来ないうちに何度押しても壊れません。進行中に 開始 を押すと、いま答えるべき質問をもう一度返すだけです。
ボタンを押しても無料枠は減りません。 Bot からの返事（reply）は 0 通です。減るのは個別カレンダーの配信とグループへの公開だけで、どちらも人数ぶん数えます。

うまくいかないとき

症状見るところ
Webhook の「検証」が 302 で失敗する302 なら正常。手順 5 を参照。転送先が accounts.google.com のときだけ本当の失敗で、手順 4 の「アクセスできるユーザー」が「全員」になっていない
ボタンを押しても返事がないGAS エディタ左「実行数」でエラーを見る。トークンが正しいか
「始めますか」が来ないトリガーが daily で毎日になっているか。設定 の管理者ID が正しいか
Bot がグループに入れない／グループID が入らない手順 1 の「グループトーク・複数人トークへの参加」が有効か。有効にしてから、Bot を外してもう一度招待する
管理者ID がわからないLINE Developers → チャネル基本設定 → 一番下「あなたのユーザーID」

更新のしかた

  1. GAS にコードを貼り直す
  2. デプロイを管理 → 鉛筆 → 「新バージョン」→ デプロイ

シートのデータはそのまま残ります。
