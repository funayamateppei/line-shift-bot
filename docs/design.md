# 当番Bot 仕様（確定版）

毎月の当番を LINE の会話だけで決める Bot。
管理者に「部制」と「日数」を聞き、当番の日を等間隔に並べたたたき台を管理者が直し、
メンバーに都合がつく日を聞いて、担当を公平に割り振り、グループへ当番表を送る。

メンバーが使うのはスマホの LINE だけ。基盤は Google Apps Script + スプレッドシートで費用は 0 円。

この文書が仕様の唯一の正本。実装はこの文書の内容に従う。

〔　〕＝ボタン。例文の年月は 2026年9月分で書いている。

---

## 1. 決定事項

| # | 項目 | 決定 |
|---|---|---|
| 1 | **文言** | 抽象語のみ。「当番」「担当」「都合がつく日」「当番表」。用途を示す具体語は使わない |
| 2 | **年月** | 文中は必ず「2026年9月分」のように年と月を書く |
| 3 | **部制** | 月ごとに一律。「1部制」か「2部制」を管理者に 1 回聞く |
| 4 | **1 日の担当人数** | 1部制 = 1 人。2部制 = 午前 1 人・午後 1 人 |
| 5 | **同日の重複** | 同じ人は 1 日に 1 回まで。午前と午後に同じ人は入れない（絶対） |
| 6 | **出られない日** | 都合がつくと答えていない日には入れない（絶対） |
| 7 | **割り当ての優先順位** | ① 埋める ② 均等（担当回数の差を最小に） |
| 8 | **連投回避** | 考慮しない |
| 9 | **当番の日のたたき台** | 月の日数 ÷ 日数。間隔は q か q+1 のどちらか。開始位置はランダム |
| 10 | **曜日・祝日** | 考慮しない（管理者が手で外す） |
| 11 | **日程の修正** | 管理者がカレンダーで日付をタップして緑／白を切り替える。〔この日程でOK〕まで何も送らない |
| 12 | **日数** | 1〜その月の日数のボタン |
| 13 | **担当の入れ替え** | 当番表シートのプルダウン。候補として出るのはその日に来られる人。**来られる人が 1 人もいない日は名簿の全員**を候補に出す（協力を募って OK をもらった人を入れるため）。どちらの場合も候補以外を直接入力できる |
| 14 | **最初から決め直す** | 機能として持たない |
| 15 | **回答 UI** | カレンダーカード。当番の日だけ押せる。押した日 = 都合がつく |
| 16 | **0 日で確定** | 1 回目は聞き返す。2 回目で「都合がつく日なし」として受け付ける |
| 17 | **回答のやり直し** | 集計が走るまでは何度でも可。最新を採用。集計後は締切 |
| 18 | **古いカードの回答** | カードに入っている年月が受付中の月と違えば「締め切りました」 |
| 19 | **メンバーへの連絡** | カレンダーは個別 push（友だち追加済みの人へ）。当番表と追加依頼はグループ |
| 20 | **管理者** | 常に 1 人。userId を `設定` シートに手で書く。Bot からは聞かない |
| 21 | **操作** | すべてボタン。文字入力は使わない |
| 22 | **管理者メニュー** | 〔開始〕〔状況〕〔中止〕。管理者へのメッセージすべてにクイックリプライで添える（リッチメニューは画像が要るので使わない） |
| 22b | **押すものを見失ったとき** | 管理者が何か発言したら〔状況〕と同じものを返す。メンバーが受付中に発言したらカレンダーを出しなおす。どちらも reply なので通数 0 |
| 23 | **開始のしかた** | 毎月 15 日 9:00 に管理者へお知らせ 1 通。始めるのは管理者が〔開始〕を押したとき |
| 23b | **対象月** | 〔開始〕のあとに管理者が選ぶ。当月・翌月・翌々月の 3 つ。機械が「押した瞬間の翌月」と決めると、公開した直後に押したときに同じ月をもう一度始めたり、お知らせを遅れて押したときに月が飛んだりする |
| 24 | **定時処理** | 15 日のお知らせと 25 日の締切連絡だけ。当番づくりは進めない。再通知しない |
| 25 | **集計** | 友だち未追加者ゼロ かつ 未回答者ゼロ になった瞬間に自動で 1 回 |
| 25b | **集計が止まったとき** | 答えない人やブロックされた人が残ると集計が走らない。〔状況〕の〔この人抜きで進める〕で進める。**未回答の人はその月だけ「都合がつく日なし」として扱い名簿は触らない**（翌月はまた届く）。**未追加の人は名簿から外す**（友だち追加し直せば戻る）。押す前に名前を見せて一度確認し、進めると誰もいなくなる場合は押せない。ずっと外したい人は名簿シートの行を削除する |
| 26 | **締切日** | 25 日 9:00 に未回答の一覧を管理者へ 1 回だけ。Bot から催促はしない |
| 26b | **お知らせ日・締切日の値** | 設定シートで 1〜28 のプルダウンから選ぶ。29〜31 は 31 日のない月で一度も発火しないので、そもそも入れられないようにする |
| 27 | **集まらないとき** | 管理者が自分で連絡する。コピーして貼れる文を Bot が出す |
| 28 | **埋まらない枠** | 空欄のまま当番表を作り、足りない日をコピー用の文で管理者に渡す。管理者がグループで募ってシートに手入力 |
| 29 | **中止** | 進行中のものをリセットして「中止しました。」だけ。**その月の回答も消す**（残すと、同じ月をやり直したときに前回の回答が数えられて誤った当番表ができる）。再開は〔開始〕 |
| 30 | **進行中の〔開始〕** | 「すでに開始されています」＋その段階の操作カードを再送 |
| 31 | **名簿** | グループ在籍 + 友だち追加 の 2 フラグ。休むときはグループを抜ける。在籍が立つのは ①友だち追加 ②グループ参加（memberJoined） ③**グループでの発言**。③は Bot が入る前からいた人を見つける手がかり（一覧 API が使えないため）。既に名簿にいる人には名前を入れるだけで在籍は触らない（〔この人抜きで進める〕で外した人が発言だけで戻らないように） |
| 32 | **未追加者** | 追加済みの人には先にカレンダーを送る。未追加者にはグループでメンションして追加を頼む |
| 33 | **友だち追加時** | reply で一言返す（0 通） |
| 34 | **管理者以外の管理者操作** | 経路がないので文なし。裏側では無視 |
| 35 | **シート** | 年度ごと 1 タブ（4 月始まり）。`当番_2026年度` = 2026/4〜2027/3 |
| 36 | **壊れないために** | 設定変更に再デプロイ不要。回答は 1 人 1 行で、答え直したら上書き（消すのは〔中止〕と、受付を始めるときだけ）。状態は 1 回だけ書く |
| 37 | **reply token 失効** | 失効したら push に切り替えず送らない |
| 38 | **送信の失敗** | つながらなくても処理を止めない。一斉送信が途中で切れても残りの人に送る。グループへの公開だけは失敗を管理者に伝え、段階を進めずに押し直せるようにする |
| 39 | **順番待ち** | シートの読み書きは 1 つずつ通す。順番が回ってこなかったら「もう一度押してください」と返す（黙って捨てない） |

### 禁止事項

- 管理者の代わりに機械が決めること（自動承認・自動公開）
- 〔この日程でOK〕の前にメンバーへ連絡すること
- 管理者以外が日程や担当を操作すること
- Bot からの催促
- 日付や時刻で当番づくりを進めること（お知らせと締切連絡だけは可）
- 具体的な用途を示す文言
- 文字入力を必要とする操作

## 2. 通数

通数は「送信対象となった人数 × push リクエスト回数」。1 リクエストに吹き出し 5 つまで入るので、管理者に吹き出し 2 つ送っても 1 通。reply は 0 通。無料枠 200 通/月。

| 送信 | 通数 |
|---|---|
| 15 日お知らせ（管理者） | 1 |
| カレンダー（メンバー各人） | n |
| 追加依頼（グループ、未追加者がいる月のみ） | n |
| 締切連絡（管理者、揃っていない月のみ） | 1 |
| 当番表（管理者） | 1 |
| 公開（グループ） | n |

**月 2n＋3 〜 3n＋3 通。** n = 20 なら 43〜63 通。

---

## 3. 名簿

| フラグ | 立つ | 下りる |
|---|---|---|
| 在籍 | Bot がいる状態でグループ参加（memberJoined）／友だち追加 | グループを抜ける（memberLeft） |
| 友だち追加 | follow | unfollow |

**メンバー = 在籍 かつ 友だち追加。** カレンダーはこの人たちに送る。
**未追加者 = 在籍 かつ 未追加。** グループでメンションして追加を頼む。

無料アカウントではグループのメンバー一覧 API が使えない。Bot を招待する前からいた人は検出できないので、**導入時に全員が一度友だち追加する**。運用マニュアルに書く。

## 4. 導入（最初の 1 回）

### 4.1 管理者
`設定` シートの「管理者ID」に管理者の userId を手で書く。Bot は何も送らない。userId の確認方法はデプロイ手順に書く。

### 4.2 友だち追加（誰でも同じ、reply）
> 友だち追加ありがとうございます。
> 当番の相談はこちらに届きます。

回答受付中で、この人にまだカレンダーを送っていなければ、続けて 6.1 のカレンダーを同じ reply で送る。

### 4.3 Bot をグループに招待（reply）
> 当番の連絡を担当する Bot です。
> この Bot を友だち追加してください。
> 当番の相談はこの Bot から届きます。

### 4.4 新しい人がグループに参加（reply）
> {名前}さん、はじめまして。
> 当番の相談を送るため、この Bot を友だち追加してください。

### 4.5 グループを抜けた
名簿の在籍を下ろす。Bot は何も送らない。

### 4.6 グループで発言した
名簿に載せる。**何も送らない**（グループの雑談に割り込まない）。

無料アカウントではメンバー一覧を取れないため、Bot が入る前からいた人を見つける
数少ない手がかりがこれ。発言のイベントには話した人の userId が入っており、
`GET /group/{gid}/member/{uid}` で名前も取れる（実測で 200）。

- 名簿にいない人 … 在籍を立てて名前を入れる。友だち追加は立てない（直接は送れないため）
- 名簿にいて名前が空の人 … 名前だけ入れる
- 名簿にいて名前もある人 … 何もしない（問い合わせもしない）

在籍を立てるのは 1 つめだけ。〔この人抜きで進める〕で外した人が、発言しただけで
戻ってくると管理者の判断が打ち消され、集計がまた止まってしまう。
グループを抜けた人が戻るときは `memberJoined` が飛ぶので、そちらで足りる。

設定シートのグループID と一致するグループの発言だけを見る。

## 5. 管理者のターン（前半）

### 5.1 15 日 9:00 お知らせ（push 1 通）
> 2026年9月分の当番づくりを始めますか？
> 〔開始〕

### 5.2 〔開始〕（reply）
何月分を作るかをたずねる。当月・翌月・翌々月の 3 つ。
> 何月分の当番づくりをしますか？
> 〔2026年8月分〕〔2026年9月分〕〔2026年10月分〕

### 5.3 対象月を押す（reply）
> 2026年9月分の当番づくりを始めます。
> 1日の担当人数を選んでください。
> 〔1部制（1人）〕〔2部制（午前・午後）〕

### 5.4 部制を押す（reply）
> 2部制ですね。
> 2026年9月の当番の日数を選んでください。
> 〔1〕〔2〕…〔30〕

### 5.5 日数を押す（reply）
たたき台カレンダー。日付を押すと緑／白が切り替わり、同じカードを更新する。**メンバーには何も送らない。**
選んでいる日は `状態` に残す。8.4 で編集の途中から戻れるようにするため。
> 2026年9月に8日、均等に散らした案です。
> 日付を押すと当番の日を付け外しできます。
> よければ〔この日程でOK〕を押してください。
> （カレンダー：当番の日＝緑）
> 〔この日程でOK〕

日付を押したあとの文：
> いま9日です。
> よければ〔この日程でOK〕を押してください。
> 〔この日程でOK〕

0 日のまま押されたら：
> 1日以上選んでください。

### 5.6 〔この日程でOK〕（reply）
ここで保存し、メンバーのターンへ。
> 2026年9月の当番の日を確定しました（8日）。
> 9/2, 9/6, 9/9, 9/13, 9/17, 9/20, 9/24, 9/28
> メンバーに都合を聞きます。全員の回答がそろったら当番表を送ります。
> 〔状況〕

## 6. メンバーのターン

### 6.1 カレンダーが届く
〔この日程でOK〕の直後。

**友だち追加済みのメンバー各人へ push（n 通）**
> 2026年9月の当番で、都合がつく日を押してください。
> 押した日は緑になります。
> 選び終わったら〔確定〕を押してください。
> （カレンダー：当番の日だけ押せる）
> 〔確定〕

**未追加者がいるときだけ、グループへ push 1 通（メンション付き）**
> {@Aさん} {@Bさん}
> 2026年9月の当番の相談を送るため、この Bot を友だち追加してください。
> 追加していただいた方から順にお聞きしています。

未追加者が追加したら、4.2 に続けてカレンダーを reply で送る。

### 6.2 〔確定〕（reply）
日付を押すたびにカードを更新（保存しない）。〔確定〕で保存。
> ありがとうございます。2026年9月は次の日で受け付けました。
> 9/2, 9/13, 9/24
> 変えたいときは、もう一度カレンダーで選んで〔確定〕を押してください。

1 日も選ばずに〔確定〕の 1 回目：
> 1日も選ばれていません。
> 2026年9月は都合がつく日がない、ということでよろしいですか？
> よろしければもう一度〔確定〕を押してください。
> 〔確定〕

2 回目はそのまま受け付け、一覧の代わりに「都合がつく日なし」と返す。

当番の日でない日が混ざっていたら落としてから保存する。

### 6.3 〔確定〕が無効なとき（reply）

| 押されたカード | いまの状態 | 返事 |
|---|---|---|
| 9月分 | 9月分を受付中 | 受け付ける |
| 9月分 | 9月分は集計済み | 「2026年9月分の回答は締め切りました。変更は管理者に連絡してください。」 |
| 9月分 | 10月分を受付中／何もしていない | 「2026年9月分の回答は締め切りました。」 |

### 6.4 自動集計
未追加者ゼロ かつ 未回答者ゼロ になった瞬間に 1 回。メンバーには何も送らない。
結果をシート `当番_2026年度` に書く。担当セルはその日に出られる人だけのプルダウン。

## 7. 管理者のターン（後半）

### 7.1 当番表が届く（push 1 通）
> 全員の回答がそろいました。
> 2026年9月の当番表です。
> 9/2　午前：Aさん　午後：Bさん
> 9/6　午前：Cさん　午後：—
> …
> 〔グループに送る〕〔担当を入れ替える（表を開く）〕

1 行目は場面で変わる。〔状況〕から見たときは「当番表を確認中です。」、
〔開始〕から戻ったときは「すでに2026年9月分は開始されています。続きはこちらです。」。

空欄があるときは同じ push に吹き出しを 2 つ先に足す（通数は変わらず 1）：
> 担当が決まらなかった日があります。
> 表を直してから〔グループに送る〕を押してください。
> グループで協力を募るときは、次の文をコピーして送ってください。

> 2026年9月6日(午後)、2026年9月20日の担当が決まっていません。ご都合がつく方は連絡をお願いします。

日付の書き方は、午前だけ空なら `2026年9月6日(午前)`、午後だけ空なら `(午後)`、
**両方とも空なら括弧なしで `2026年9月20日` の 1 つにまとめる。**

### 7.2 〔担当を入れ替える（表を開く）〕（reply）
> 当番表を開いて担当を直してください。
> 直したあと〔グループに送る〕を押すと、シートの内容でそのまま送ります。
> {シートの URL}
> 〔グループに送る〕

当番表の行の形
- 2部制: `9/2　午前：山田さん　午後：佐藤さん`
- 1部制: `9/2　山田さん`
- 決まっていない枠: `—`

### 7.3 〔グループに送る〕
シートの最新内容をグループへ push 1 通：
> 2026年9月の当番表です。
> 9/2　午前：Aさん　午後：Bさん
> 9/6　午前：Cさん　午後：Dさん
> …

管理者へ reply：
> グループに送りました。2026年9月分はこれで完了です。

送れなかったときは段階を進めず、押し直せるようにする：
> グループに送れませんでした。
> しばらく待ってから、もう一度〔グループに送る〕を押してください。
> 〔グループに送る〕〔担当を入れ替える（表を開く）〕

## 8. 途中操作

### 8.1 25 日 9:00 締切連絡（push 1 通、吹き出し 2 つ）
揃っていない月だけ。
> 2026年9月の回答がまだそろっていません。
> 未回答：A、B
> 未追加：C
> 次の文をコピーしてグループに送ってください。

> Aさん、Bさん、回答お願いします。Cさん、Bot の友だち追加をお願いします。

未追加がなければ後半は省く。

### 8.2 〔状況〕（reply）
- 何も進めていない
  > いま進めているものはありません。
  > 〔開始〕
- 日程を決めている途中
  > 2026年9月分の日程を決めている途中です。
  > 〔中止〕
- 回答受付中
  > 2026年9月分の回答を受け付け中です。
  > 回答済み：12人　未回答：A、B　未追加：C
  > 次の文をコピーしてグループに送れます。

  > Aさん、Bさん、回答お願いします。Cさん、Bot の友だち追加をお願いします。

  ボタンは〔中止〕。未回答か未追加の人がいるときは〔この人抜きで進める〕も出す。
- 当番表を確認中 … 7.1 の当番表そのものを返す（先頭が「当番表を確認中です。」に変わる）。
  集計のときの送信に失敗していても、ここで取り出せる
- 公開済み
  > 2026年9月分は公開済みです。
  > 〔開始〕
- 何月分を作るか選んでいる途中
  > 何月分を作るか選んでいる途中です。
  > 〔中止〕

### 8.3 〔この人抜きで進める〕（reply）
答えない人やブロックされた人が残ると集計が走らない。そこから抜け出す操作。
未回答の人がいるか未追加の人がいるときだけ、〔状況〕の受付中にボタンが出る。

1 回目は名前を見せて聞き返す：
> 鈴木さんは、2026年9月は都合がつく日なしとして進めます。
> 田中さんは名簿から外します。友だち追加すればまた入ります。
> よろしければもう一度〔この人抜きで進める〕を押してください。

## 10. 当番の日のたたき台

```
D = 月の日数, N = 当番の日数 (1 ≤ N ≤ D)
q = floor(D / N)          基本の間隔
r = D mod N               1 日広い間隔の数
間隔 = [q+1] × r 個 + [q] × (N−r) 個 → シャッフル
offset = 0〜q−1 のランダム
1 日目 = 1 + offset、以降は間隔を足していく
```

## 11. 割り当てロジック

**入力**: 当番の日、部制、各メンバーの都合がつく日、メンバー一覧
**出力**: 枠（日 × 午前/午後）ごとの担当者。入れられる人がいない枠は空欄

**絶対**
- 同じ人は 1 日に 1 回まで
- 都合がつくと答えていない日には入れない

**優先**
1. 埋める
2. 均等（担当回数の最大と最小の差を最小に）

**手順**
1. 枠を候補者が少ない順に並べる
2. 各枠で、候補者のうちその日にまだ入っていない人だけ残す。残らなければ空欄
3. 残った中で担当回数が最少の人からランダムに 1 人
4. 全部埋めたあと、玉突きの付け替え（多い人 → 少ない人、途中の人を経由してよい）を見つからなくなるまで繰り返す

**空欄になるケース**
- (a) その日に都合がつく人が誰もいない
- (b) 都合がつく人が全員その日の別枠に入っている

## 13. 技術

- Google Apps Script (V8)。`SpreadsheetApp.openById()`
- Webhook: `doPost`。ヘッダが読めず署名検証はしない。ウェブアプリ URL が推測不能な長さであることで足りるとする（漏れても困る情報はない）
- **シートは Bot が自動で作る**。初回に `setup()` を 1 回実行すると 5 タブをこの文書のデザインで作成する。`当番_YYYY年度` は年度が変わった最初の集計で自動追加。既にあるタブは作り直さない
- **管理者に届くものには必ずメニューを添える**。quick reply は最後のメッセージにしか残らず、管理者もメンバーの一人なのでカレンダーが届くたびに消えてしまう。送信の入口（`reply_` / `push_`）で相手が管理者かを見て添える。グループ宛てには添えない（quick reply はその場の全員に見える）
- **Flex の文字に URL を書いてもリンクにならない**。自動でリンクになるのは普通のテキストメッセージだけ。開かせたい URL は `uri` のボタンにする（〔当番表を開く〕）
- **無料アカウントでもメンバー 1 人ずつの情報は取れる**（実測）。`GET /group/{gid}/member/{uid}` は 200 を返す。一覧の `GET /group/{gid}/members/ids` は 403（`Access to this API is not available for your account`）
- **セルの表示形式に頼りきらない**。`appendRow` は書いたセルの表示形式を既定に戻すので、シート作成時に置いた `@`（テキスト）が消え、`2026-09` が日付として保存される。表示は `2026-09` のままなので目では気づけない。書くときは行ごとに `@` を置き直し、読むときは `ymOfCell_()` で Date も文字列に戻してから照合する（人がシートを直接編集した場合にも効く）
- 定時: 毎日 9:00 のトリガー 1 本。15 日なら 5.1、25 日なら 8.1 を送るだけ
- LINE: Flex Message（カレンダー・当番表）、postback、`textV2`＋`substitution` のメンション
- reply token は 1 回だけ使える。失効したら送らない
- シートの読み書きが重ならないよう、イベント処理は `LockService` で 1 つずつ通す
- メンション（`textV2`）が失敗したら、名前を並べただけの文に切り替えて送る
- メンバーのカレンダーで選んでいる日は、確定まで保存せずボタンの `postback` に載せて持ち回る（1〜31 日をビットで表す）
- 集計の条件は、回答が入ったときだけでなく、誰かがグループを抜けたとき・友だち追加したとき・〔状況〕を押したときにも見る。送信の失敗できっかけを取りこぼしても、〔状況〕で取り戻せる
- 名簿に同じ userId が 2 行あっても二重に数えない（後の行を採用する）
- `状態` の当番の日に、その月に無い日（30 日の月の 31 日など）が手で書かれていても落とす
