# 当番Bot 仕様（確定版）

毎月の当番を LINE の会話だけで決める Bot。
管理者に「部制」と「日数」を聞き、当番の日を等間隔に並べたたたき台を管理者が直し、
メンバーに都合がつく日を聞いて、担当を公平に割り振り、グループへ当番表を送る。

メンバーが使うのはスマホの LINE だけ。基盤は Google Apps Script + スプレッドシートで費用は 0 円。

この文書が仕様の唯一の正本。実装はこの文書の内容に従う。

〔　〕＝ボタン。例文の年月は 2026年9月分で書いている。

### 禁止事項

- 管理者の代わりに機械が決めること（自動承認・自動公開）
- 〔この日程でOK〕の前にメンバーへ連絡すること
- 管理者以外が日程や担当を操作すること
- Bot からの催促
- 日付や時刻で当番づくりを進めること（お知らせと締切連絡だけは可）
- 具体的な用途を示す文言
- 文字入力を必要とする操作

## 2. 通数

通数は「送信対象となった人数 × push リクエスト回数」。1 リクエストに吹き出し 5 つまで入るので、管理者に吹き出し 2 つ送っても 1 通。reply は 0 通。無料枠 200 通/月。

| 送信 | 通数 |
|---|---|
| 15 日お知らせ（管理者） | 1 |
| カレンダー（メンバー各人） | n |
| 追加依頼（グループ、未追加者がいる月のみ） | n |
| 締切連絡（管理者、揃っていない月のみ） | 1 |
| 当番表（管理者） | 1 |
| 公開（グループ） | n |

**月 2n＋3 〜 3n＋3 通。** n = 20 なら 43〜63 通。

## 3. 名簿

| フラグ | 立つ | 下りる |
|---|---|---|
| 在籍 | Bot がいる状態でグループ参加（memberJoined）／友だち追加 | グループを抜ける（memberLeft） |
| 友だち追加 | follow | unfollow |

**メンバー = 在籍 かつ 友だち追加。** カレンダーはこの人たちに送る。
**未追加者 = 在籍 かつ 未追加。** グループでメンションして追加を頼む。

無料アカウントではグループのメンバー一覧 API が使えない。Bot を招待する前からいた人は検出できないので、**導入時に全員が一度友だち追加する**。運用マニュアルに書く。

## 4. 導入（最初の 1 回）

### 4.1 管理者
`設定` シートの「管理者ID」に管理者の userId を手で書く。Bot は何も送らない。userId の確認方法はデプロイ手順に書く。

### 4.2 友だち追加（誰でも同じ、reply）
> 友だち追加ありがとうございます。
> 当番の相談はこちらに届きます。

回答受付中で、この人にまだカレンダーを送っていなければ、続けて 6.1 のカレンダーを同じ reply で送る。

### 4.3 Bot をグループに招待（reply）
> 当番の連絡を担当する Bot です。
> この Bot を友だち追加してください。
> 当番の相談はこの Bot から届きます。

### 4.4 新しい人がグループに参加（reply）
> {名前}さん、はじめまして。
> 当番の相談を送るため、この Bot を友だち追加してください。

### 4.5 グループを抜けた
名簿の在籍を下ろす。Bot は何も送らない。

## 6. メンバーのターン

### 6.1 カレンダーが届く
〔この日程でOK〕の直後。

**友だち追加済みのメンバー各人へ push（n 通）**
> 2026年9月の当番で、都合がつく日を押してください。
> 押した日は緑になります。
> 選び終わったら〔確定〕を押してください。
> （カレンダー：当番の日だけ押せる）
> 〔確定〕

**未追加者がいるときだけ、グループへ push 1 通（メンション付き）**
> {@Aさん} {@Bさん}
> 2026年9月の当番の相談を送るため、この Bot を友だち追加してください。
> 追加していただいた方から順にお聞きしています。

未追加者が追加したら、4.2 に続けてカレンダーを reply で送る。

### 6.2 〔確定〕（reply）
日付を押すたびにカードを更新（保存しない）。〔確定〕で保存。
> ありがとうございます。2026年9月は次の日で受け付けました。
> 9/2, 9/13, 9/24
> 変えたいときは、もう一度カレンダーで選んで〔確定〕を押してください。

1 日も選ばずに〔確定〕の 1 回目：
> 1日も選ばれていません。
> 2026年9月は都合がつく日がない、ということでよろしいですか？
> よろしければもう一度〔確定〕を押してください。
> 〔確定〕

2 回目はそのまま受け付け、一覧の代わりに「都合がつく日なし」と返す。

### 6.3 〔確定〕が無効なとき（reply）

| 押されたカード | いまの状態 | 返事 |
|---|---|---|
| 9月分 | 9月分を受付中 | 受け付ける |
| 9月分 | 9月分は集計済み | 「2026年9月分の回答は締め切りました。変更は管理者に連絡してください。」 |
| 9月分 | 10月分を受付中／何もしていない | 「2026年9月分の回答は締め切りました。」 |

### 6.4 自動集計
未追加者ゼロ かつ 未回答者ゼロ になった瞬間に 1 回。メンバーには何も送らない。
結果をシート `当番_2026年度` に書く。担当セルはその日に出られる人だけのプルダウン。

## 10. 当番の日のたたき台

```
D = 月の日数, N = 当番の日数 (1 ≤ N ≤ D)
q = floor(D / N)          基本の間隔
r = D mod N               1 日広い間隔の数
間隔 = [q+1] × r 個 + [q] × (N−r) 個 → シャッフル
offset = 0〜q−1 のランダム
1 日目 = 1 + offset、以降は間隔を足していく
```

## 11. 割り当てロジック

**入力**: 当番の日、部制、各メンバーの都合がつく日、メンバー一覧
**出力**: 枠（日 × 午前/午後）ごとの担当者。入れられる人がいない枠は空欄

**絶対**
- 同じ人は 1 日に 1 回まで
- 都合がつくと答えていない日には入れない

**優先**
1. 埋める
2. 均等（担当回数の最大と最小の差を最小に）

**手順**
1. 枠を候補者が少ない順に並べる
2. 各枠で、候補者のうちその日にまだ入っていない人だけ残す。残らなければ空欄
3. 残った中で担当回数が最少の人からランダムに 1 人
4. 全部埋めたあと、玉突きの付け替え（多い人 → 少ない人、途中の人を経由してよい）を見つからなくなるまで繰り返す

**空欄になるケース**
- (a) その日に都合がつく人が誰もいない
- (b) 都合がつく人が全員その日の別枠に入っている

### `当番_YYYY年度` の形

| 年月 | 日 | 曜 | 午前 | 午後 | 来られる人 |
|---|---|---|---|---|---|
| 2026年9月 | | | 2部制 | | |
| 2026年9月 | 2 | 水 | 山田 | | 山田 |
| 2026年9月 | 17 | 木 | | | |
| 2026年10月 | | | 1部制 | | |
| 2026年10月 | 3 | 土 | 山田 | — | 山田, 佐藤 |

- 月の先頭に見出し行（日が空、午前に部制）。見出し行は薄い青の帯
- **午前・午後だけが編集セル**（薄緑）。プルダウンは Bot が集計時に**セルごとに候補リストを直接設定**する（その日に来られる人＋空欄）。「範囲から選ぶ」＋数式は使えないため
- 担当が空欄の枠は条件付き書式で**赤く**なる
- 1部制の月は午後に「—」を入れ、グレー表示
- 曜は土＝青、日＝赤
- 来られる人は Bot が書く参考情報（グレーの小さい字）。管理者は触らない

### ほかのタブの見た目

- 全タブ共通：1 行目はスレート色の帯に白太字、固定
- `設定`：値の列（B）だけ薄黄＝編集してよい印。C 列は説明
- `名簿`：在籍・友だち追加はチェックボックス。在籍だが未追加の行は薄橙、抜けた人はグレー字
- `状態`・`回答ログ`：Bot が書く。人は触らない

### 壊れないために
- 設定はシートから毎回読む
- 回答は追記のみ
- 状態は処理の最後に 1 回書く
- 送信に失敗しても状態は壊れない。管理者が〔状況〕で確認できる

## 13. 技術

- Google Apps Script (V8)。`SpreadsheetApp.openById()`
- Webhook: `doPost`。ヘッダが読めず署名検証はしない。ウェブアプリ URL が推測不能な長さであることで足りるとする（漏れても困る情報はない）
- **シートは Bot が自動で作る**。初回に `setup()` を 1 回実行すると 5 タブをこの文書のデザインで作成する。`当番_YYYY年度` は年度が変わった最初の集計で自動追加。既にあるタブは作り直さない
- 定時: 毎日 9:00 のトリガー 1 本。15 日なら 5.1、25 日なら 8.1 を送るだけ
- LINE: Flex Message（カレンダー・当番表）、postback、`textV2`＋`substitution` のメンション
- reply token は 1 回だけ使える。失効したら送らない
